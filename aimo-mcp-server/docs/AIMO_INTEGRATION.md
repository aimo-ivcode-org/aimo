# Integration with aimo-mcp-client

This guide explains how to connect an `aimo-mcp-server` instance to `aimo-mcp-client` so that tools and prompts from your MCP server can be discovered and used by AIMO applications.

## Overview

`aimo-mcp-client` is designed to discover and consume MCP servers built with `aimo-mcp-server`. The integration enables:

- **Tool Discovery**: All `@McpTool` methods are exposed to AIMO as callable tools
- **Prompt Discovery**: All `@McpPrompt` methods are available as system message templates
- **Scope Awareness**: Tools and prompts respect AIMO's chat scope system
- **Automatic Schema Handling**: OpenRPC schemas generated by the server are used by the client

## Architecture

```
┌──────────────────────────────────────────────────────────────┐
│                    AIMO Application                          │
│  (examples/simple-ollama, examples/mcp-client-ollama, etc.)  │
└──────────────────────┬───────────────────────────────────────┘
                       │
        ┌──────────────▼───────────────┐
        │    aimo-mcp-client           │
        │  (discovers servers)          │
        │  (exposes tools/prompts)      │
        └──────────────┬────────────────┘
                       │ HTTP
        ┌──────────────▼───────────────┐
        │   aimo-mcp-server            │
        │  (serves tools/prompts)       │
        └──────────────────────────────┘
        
        (One or more servers can be connected)
```

## Configuration

### 1. Configure aimo-mcp-server

Start your MCP server and ensure it's reachable:

```yaml
# In your aimo-mcp-server application.yml
aimo:
  mcp-server:
    name: "my-tools"
    version: "1.0.0"
    transports:
      http:
        enabled: true
        basePath: "/mcp"
```

Start the server:
```bash
./gradlew.bat :examples:your-mcp-app:bootRun
# Server runs on http://localhost:9090/mcp
```

### 2. Configure aimo-mcp-client

In your AIMO application, configure the MCP client to discover your server:

```yaml
# In your AIMO application's application.yml
aimo:
  mcp:
    required: false                # false = graceful degradation if server unreachable
    discovery-interval-minutes: 0  # 0 = no periodic refresh
    
    servers:
      - id: "my-tools"             # Server identifier (appears in tool names)
        transport: "http"           # or "sse" or "stdio"
        url: "http://localhost:9090/mcp"
        auth:
          type: "none"              # or "bearer", "api-key", etc.
        scope: ["global"]            # Scope restriction (empty = global only)
```

### 3. Start AIMO Application

```bash
./gradlew.bat :examples:mcp-client-ollama:bootRun
```

The application will:
1. Connect to the MCP server
2. Discover all tools and prompts
3. Expose them with server-id prefix (e.g., `my-tools:add`)
4. Make them available in chat context

## Tool Naming Convention

Tools from MCP servers are prefixed with the server ID to avoid collisions:

**Local tools (defined in aimo-core):**
```
tool_name
```

**Remote tools (from MCP servers):**
```
{server-id}:tool_name
```

**Example:**
```
calculator:add
calculator:divide
calculator:multiply
search:web-search
```

## Prompt Naming Convention

System messages from MCP servers are similarly prefixed:

**Local prompts:**
```
system_message_name
```

**Remote prompts:**
```
{server-id}:prompt_name
```

**Example:**
```
calculator:calculator-help
search:search-guidelines
```

## Scope Integration

If your MCP server defines scopes, `aimo-mcp-client` respects them:

**In aimo-mcp-server:**
```yaml
aimo:
  mcp-server:
    servers:
      - id: "admin-tools"
        scope: ["admin", "research"]  # Only available in these scopes
```

**Usage:**
- Tools are only available when the chat scope matches
- Empty scope list = available globally

**In aimo-core (AIMO), scopes can be set:**
```yaml
aimo:
  scope:
    admin:
      tool-refs: ["admin-tools:*", "local-admin-tool"]
      system-message-refs: []
```

## Multi-Server Setup

You can connect multiple MCP servers:

```yaml
aimo:
  mcp:
    servers:
      - id: "calculator"
        url: "http://localhost:9090/mcp"
        scope: ["global"]
      
      - id: "search"
        url: "http://localhost:8081/mcp"
        scope: ["research"]
      
      - id: "admin-tools"
        url: "http://localhost:8082/mcp"
        scope: ["admin"]
```

Tools from all servers are available:
- `calculator:add`
- `search:web-search`
- `admin-tools:user-management`

## Error Handling & Resilience

### Server Unreachable

If `required: false`:
- Startup succeeds
- Tools/prompts from that server are unavailable
- Other servers/tools still work

If `required: true`:
- Startup fails if any server unreachable

### Tool Execution Failure

If tool invocation fails:
- Error is caught and returned to AIMO
- Formatted as MCP error response
- AIMO handles gracefully (may retry, report to user, etc.)

### Configuration Issues

Common issues:
- **Wrong URL**: Verify server is running at configured URL
- **Wrong server ID**: Must match server `id` in configuration
- **Scope mismatch**: Tool may not be available in current scope
- **Tool name format**: Use full name with server ID prefix

## Monitoring & Debugging

### Check Connected Servers

In logs, look for:
```
[INFO] Initializing MCP server: my-tools
[INFO] Discovered tools: add, subtract, multiply, divide
[INFO] Discovered prompts: calculator-help, arithmetic-tutorial
```

### Test Server Connectivity

```bash
# From AIMO host:
curl -X POST http://localhost:9090/mcp/ \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

### Enable Debug Logging

```yaml
logging:
  level:
    org.ivcode.aimo.mcp.client: DEBUG
    org.ivcode.aimo.server.mcp: DEBUG
```

## Best Practices

1. **Server Lifecycle**: Start all MCP servers before starting AIMO app
2. **Error Handling**: Set `required: false` for optional servers
3. **Naming**: Use clear, descriptive server IDs (e.g., `calc`, `search`, `db`)
4. **Scopes**: Restrict tools to appropriate scopes for security/clarity
5. **Monitoring**: Log tool invocations for debugging
6. **Testing**: Test tools independently before integrating with AIMO

## Troubleshooting

### Tools not appearing in AIMO

- [ ] Verify server is running: `curl http://localhost:9090/mcp/tools/list`
- [ ] Check configuration URL is correct
- [ ] Verify server ID matches in config
- [ ] Check scope restrictions
- [ ] Enable debug logging

### Tool invocation fails

- [ ] Check tool parameters match schema
- [ ] Verify parameter types are correct
- [ ] Review server logs for execution errors
- [ ] Test tool directly via HTTP

### Scope issues

- [ ] Verify scope list in server config
- [ ] Check AIMO scope configuration includes server scope
- [ ] Use `global` scope for universal availability
